# Mandatory session execution protocol

Applies to every new session, resumed chat, other AI and pipeline step. User instructions prevail. Inspect the current task and artifacts first. Read root rules, nearest stage context, affected source, owning skill entry and relevant references. Record only actual reads and decisions. Never run a production step simply because it is next in a script.
The repository owns the workflow; the agent does not select an alternative pipeline. Recover the latest user-authorized task, including corrections, before acting. Work only within that scope under the repo's contracts. Do not skip/reorder required stages, silently lower quality, install/migrate tools or initiate unrelated work. A request to update rules permits rule/tooling changes and relevant checks; it does not permit film/script/voice/asset generation or rendering. Existing approval for a historic film is not authorization to create a different film/version. If prerequisites or authorization are absent, report the specific gap; never fabricate them. Continue already-authorized necessary work without asking for repeated approval.

The read-only command `python animation-studio/scripts/v6_session.py requirements <operation>` lists the minimum files for that operation. It does not read or acknowledge them on the agent's behalf. Read additional affected prompts/schemas/source and relevant skill references when needed.

After reading, acknowledge each intended operation with `v6_session.py ack --session <current-session-id> --actor <agent-name> --scope <exact-film-slug> --operation <operation> --intent <actual-user-request> --read <repo-relative-path>` (repeat `--read` for each actual read) and `--decision <decision>` (repeat as needed). The receipt includes file hashes. Use CODEX_THREAD_ID when supplied by Codex; otherwise set V6_SESSION_ID to a fresh unique ID for this session and use it in `--session`. Do not reuse another session's receipt or ID. Re-acknowledge after rules/source change. A resumed agent must reread before acknowledging; no automatic receipt creation in pipeline commands.

Operations: init, spec, preview, render, legacy-tag, legacy-spec, legacy-pipeline, legacy-tts, legacy-asr, legacy-align, asset-intake, media-download, legacy-render. Only declared operations for the exact scope run. Preview produces named styleframe/animatic/pilot/QA evidence, never delivery approval. Router children need their own declared reads/decisions; a router receipt cannot authorize all later steps. Legacy utilities also require --legacy-v5 and an existing historic film. New work uses typed v6 packets. Legacy regeneration still needs actual user authorization to alter historic output.

Receipts live in `output/<slug>/v6/sessions/`. Initialization permits a sessions-only directory, never overwrites an existing packet. Executed steps append the actual receipt to the packet's production.rule_reads. Read-only inspections, requirements, validators and tests need no production execution receipt. A receipt never grants creative approval, factual review, platform review or full-render authorization. Existing real user authorization persists; do not ask again merely to satisfy this protocol.

`npm run build` uses render_v6.py; provide the slug, --entry and --composition. Direct Remotion CLI, custom scripts and imported functions that bypass the guarded entry points are prohibited by repo policy. The guard checks identity/scope/declared operations/current reading hashes before service calls or writes. It cannot prove human/AI comprehension or prevent a process with filesystem access from rewriting its own tools. Do not describe it as an adversarial security sandbox.
For repo maintenance, store an explicitly labelled maintenance read/decision/check log at `output/<maintenance-slug>/v6/production.json`; it is not a film packet and must never be presented as production approval. Current operation receipts are for production commands, not permission to do unrelated work. Default SFX generation is not authorized merely by listing media-download: sound decisions/event ownership still come from the reviewed film packet. Set V6_FILM_SLUG for that legacy media utility only when its actual use is authorized.
